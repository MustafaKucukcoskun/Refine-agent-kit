# /migrate - Database Migration Management

$ARGUMENTS

---

## Purpose

Create, apply, and manage database migrations for Python backend projects using Alembic (SQLAlchemy) or Django migrations.

---

## Sub-commands

```
/migrate                    - Show migration status
/migrate create [name]      - Create new migration
/migrate apply              - Apply pending migrations (upgrade head)
/migrate rollback           - Rollback last migration
/migrate rollback [n]       - Rollback n migrations
/migrate history            - Show migration history
/migrate diff               - Show pending schema changes
```

---

## Domain Detection

| ORM | Migration Tool | Config File |
|-----|---------------|-------------|
| SQLAlchemy | Alembic | `alembic.ini` |
| Django | Django Migrations | `manage.py` |
| Tortoise ORM | Aerich | `pyproject.toml` |
| Peewee | peewee-migrate | — |

---

## Behavior

### Alembic (SQLAlchemy)

```bash
# Check status
alembic current
alembic history --verbose

# Create migration
alembic revision --autogenerate -m "add_users_table"

# Apply
alembic upgrade head

# Rollback
alembic downgrade -1
```

### Django

```bash
# Check status
python manage.py showmigrations

# Create migration
python manage.py makemigrations [app_name]

# Apply
python manage.py migrate

# Rollback
python manage.py migrate [app_name] [migration_name]
```

---

## Pre-Migration Checklist

```markdown
- [ ] Database backup taken (production)
- [ ] Models match intended schema
- [ ] No destructive changes without explicit confirmation
- [ ] Migration is reversible (has downgrade)
- [ ] Test migration on staging first
```

| Table | Action | Columns |

### Commands Executed
```bash
[actual commands run]
```

---

## Key Principles

- **Always backup before production migrations**
- **Review autogenerated migrations** — they can miss edge cases
- **Test downgrade path** — ensure rollback works
- **One logical change per migration** — don't bundle unrelated changes
